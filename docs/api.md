# API Reference

This document describes the HTTP endpoints exposed by the Go Order Management API.

## Base URL

For local development, the API is available at:

```text
http://localhost:<configured-port>
```

The port is controlled by the application configuration.

## Health Check

### `GET /health`

Checks whether the HTTP server is responding.

**Success response**

- Status: `200 OK`
- Content-Type: plain text
- Body:

```text
OK
```

## Customer API

### Create Customer

`POST /customers`

Creates a new customer.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json
{
  "name": "John Doe",
  "email": "john.doe@example.com"
}
```

| Field   | Type   | Required | Description              |
| ------- | ------ | -------- | ------------------------ |
| `name`  | string | Yes      | Customer's name          |
| `email` | string | Yes      | Customer's email address |

The request body is limited to 1 MiB. Unknown JSON fields and additional JSON values are rejected.

**Success response**

- Status: `201 Created`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john.doe@example.com",
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

The ID and timestamps are generated by the database.

**Error responses**

| Status                         | Description                                                                        |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| `400 Bad Request`              | Invalid JSON, unknown fields, multiple JSON values, invalid name, or invalid email |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                                         |
| `500 Internal Server Error`    | Unexpected server or persistence error                                             |

### Get Customer by ID

`GET /customers/{id}`

Retrieves a customer using their ID.

**Example request**

```http
GET /customers/1
```

The ID must be a positive base-10 integer that fits in an `int64`.

**Success response**

- Status: `200 OK`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john.doe@example.com",
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

**Error responses**

| Status                      | Description                            |
| --------------------------- | -------------------------------------- |
| `400 Bad Request`           | Invalid or non-positive customer ID    |
| `404 Not Found`             | Customer does not exist                |
| `500 Internal Server Error` | Unexpected server or persistence error |

## Product API

### Create Product

`POST /products`

Creates a new product and its initial inventory record.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json
{
  "sku": "LAPTOP-001",
  "name": "Laptop",
  "description": "Development laptop",
  "price": 7500000
}
```

| Field         | Type    | Required | Description            |
| ------------- | ------- | -------- | ---------------------- |
| `sku`         | string  | Yes      | Unique product SKU     |
| `name`        | string  | Yes      | Product name           |
| `description` | string  | No       | Product description    |
| `price`       | integer | Yes      | Product price in paise |

**Note:** The `price` field is represented in paise. For example, `7500000` represents ₹75,000.00.

The request body is limited to 1 MiB. Unknown JSON fields and additional JSON values are rejected.

**Success response**

- Status: `201 Created`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "sku": "LAPTOP-001",
  "name": "Laptop",
  "description": "Development laptop",
  "price": 7500000,
  "status": "active",
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

The ID and timestamps are generated by the database.

**Error responses**

| Status                         | Description                                                                 |
| ------------------------------ | --------------------------------------------------------------------------- |
| `400 Bad Request`              | Invalid JSON, unknown fields, multiple JSON values, or invalid product data |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                                  |
| `500 Internal Server Error`    | Unexpected server or persistence error                                      |

## Inventory API

Inventory tracks a product's physical quantity and reserved quantity. Available quantity is calculated as:

```text
available_quantity = physical_quantity - reserved_quantity
```

### Get Inventory by Product ID

`GET /products/{id}/inventory`

Retrieves inventory information for a product.

**Example request**

```http
GET /products/1/inventory
```

**Success response**

- Status: `200 OK`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "product_id": 1,
  "physical_quantity": 20,
  "reserved_quantity": 5,
  "available_quantity": 15,
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

**Error responses**

| Status                      | Description                              |
| --------------------------- | ---------------------------------------- |
| `400 Bad Request`           | Invalid or non-positive product ID       |
| `404 Not Found`             | Inventory does not exist for the product |
| `500 Internal Server Error` | Unexpected server or persistence error   |

### Adjust Physical Quantity

`PATCH /products/{id}/inventory/physical-quantity`

Adjusts the physical quantity of a product's inventory.

The adjustment is expressed as a signed delta:

- Positive values increase physical quantity.
- Negative values decrease physical quantity.
- Zero is not a valid adjustment.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json
{
  "delta": 20
}
```

| Field   | Type    | Required | Description                |
| ------- | ------- | -------- | -------------------------- |
| `delta` | integer | Yes      | Signed quantity adjustment |

**Success response**

- Status: `204 No Content`
- No response body.

**Error responses**

| Status                         | Description                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------- |
| `400 Bad Request`              | Invalid product ID, invalid JSON, or zero adjustment                            |
| `404 Not Found`                | Inventory does not exist for the product                                        |
| `409 Conflict`                 | Adjustment would reduce physical quantity below zero or below reserved quantity |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                                      |
| `500 Internal Server Error`    | Unexpected server or persistence error                                          |

### Reserve Stock

`POST /products/{id}/inventory/reservations`

Reserves available stock for a product.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json
{
  "quantity": 5
}
```

| Field      | Type    | Required | Description                  |
| ---------- | ------- | -------- | ---------------------------- |
| `quantity` | integer | Yes      | Positive quantity to reserve |

**Success response**

- Status: `204 No Content`
- No response body.

**Error responses**

| Status                         | Description                                                |
| ------------------------------ | ---------------------------------------------------------- |
| `400 Bad Request`              | Invalid product ID, invalid JSON, or non-positive quantity |
| `404 Not Found`                | Inventory does not exist for the product                   |
| `409 Conflict`                 | Requested quantity exceeds available stock                 |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                 |
| `500 Internal Server Error`    | Unexpected server or persistence error                     |

### Release Reserved Stock

Releases a previously reserved quantity of stock.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json

  "quantity": 5
}
```

| Field      | Type    | Required | Description                  |
| ---------- | ------- | -------- | ---------------------------- |
| `quantity` | integer | Yes      | Positive quantity to release |

**Success response**

- Status: `204 No Content`
- No response body.

**Error responses**

| Status                         | Description                                                |
| ------------------------------ | ---------------------------------------------------------- |
| `400 Bad Request`              | Invalid product ID, invalid JSON, or non-positive quantity |
| `404 Not Found`                | Inventory does not exist for the product                   |
| `409 Conflict`                 | Requested quantity exceeds reserved stock                  |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                 |
| `500 Internal Server Error`    | Unexpected server or persistence error                     |

## Error Response Format

API errors use a consistent JSON structure:

```json
{
  "error": "customer not found"
}
```

The error message is intended for API consumers. Internal error details are not exposed in HTTP responses.

## Current API Scope

The current API supports:

- HTTP health checks
- Customer creation and retrieval by ID
- Product creation and retrieval by ID
- Inventory retrieval by product ID
- Physical inventory quantity adjustments
- Stock reservations and reservation releases

The following capabilities are not currently part of the implemented API:

- Authentication and authorization
- Rate limiting
- Customer updates and deletion
- Product updates and deletion
- Order creation and cancellation
- Automatic inventory deduction through order processing
- Coordination between order processing and inventory operations
