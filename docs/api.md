# Customer HTTP API

This document describes the customer endpoints exposed by the Go Order Management API.

## Base URL

For local development, the API is available at:

```text
http://localhost:<configured-port>
```

The port is controlled by the application configuration.

## Health Check

### `GET /health`

Checks whether the HTTP server is responding.

**Success response**

- Status: `200 OK`
- Content-Type: plain text
- Body:

```text
OK
```

## Create Customer

### `POST /customers`

Creates a new customer.

**Request headers**

```http
Content-Type: application/json
```

**Request body**

```json
{
  "name": "John Doe",
  "email": "john.doe@example.com"
}
```

| Field   | Type   | Required | Description              |
| ------- | ------ | -------- | ------------------------ |
| `name`  | string | Yes      | Customer's name          |
| `email` | string | Yes      | Customer's email address |

The request body is limited to 1 MiB. Unknown JSON fields and additional JSON values are rejected.

**Success response**

- Status: `201 Created`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john.doe@example.com",
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

The ID and timestamps are generated by the database.

**Error responses**

| Status                         | Description                                                                        |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| `400 Bad Request`              | Invalid JSON, unknown fields, multiple JSON values, invalid name, or invalid email |
| `413 Request Entity Too Large` | Request body exceeds 1 MiB                                                         |
| `500 Internal Server Error`    | Unexpected server or persistence error                                             |

## Get Customer by ID

### `GET /customers/{id}`

Retrieves a customer using their ID.

**Example request**

```http
GET /customers/1
```

The ID must be a positive base-10 integer that fits in an `int64`.

**Success response**

- Status: `200 OK`
- Content-Type: `application/json`

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john.doe@example.com",
  "created_at": "2026-11-19T10:30:00Z",
  "updated_at": "2026-11-19T10:30:00Z"
}
```

**Error responses**

| Status                      | Description                            |
| --------------------------- | -------------------------------------- |
| `400 Bad Request`           | Invalid or non-positive customer ID    |
| `404 Not Found`             | Customer does not exist                |
| `500 Internal Server Error` | Unexpected server or persistence error |

## Error Response Format

API errors use a consistent JSON structure:

```json
{
  "error": "customer not found"
}
```

The error message is intended for API consumers. Internal error details are not exposed in HTTP responses.

## Current API Scope

The current API supports:

- Customer creation
- Customer retrieval by ID
- HTTP health checks

Authentication, authorization, rate limiting, customer updates, and customer deletion are not currently part of this API implementation.
